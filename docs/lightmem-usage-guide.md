# LightMem Memory Plugin 使用ガイド

## 概要

LightMemMemoryPluginは、論文「LIGHTMEM: LIGHTWEIGHT AND EFFICIENT MEMORY-AUGMENTED GENERATION」(arXiv 2510.18866)のエッセンスをALIM 4.0に適応した高度なメモリプラグインです。

## 主な特徴

### 3段階記憶モデル

1. **感覚記憶 (Sensory Memory)**
   - 直近20ターンの重要なイベントをバッファリング
   - 重要度スコアリングによる自動フィルタリング
   - TALK、TRADE等の社会的相互作用を優先

2. **短期記憶 (Short-term Memory)**
   - カテゴリ別に記憶を整理:
     - 社会的相互作用: TALK, TRADE
     - 生存活動: CHARGE, ミッション
     - 移動: MOVE
     - 危機: 低ライフ状態、他者の死
   - 各カテゴリ最大5件保持

3. **長期記憶 (Long-term Memory)**
   - 統計情報:
     - 各キャラクターとの相互作用回数
     - 資源の提供/受領数
     - ミッション成功/失敗数
   - マイルストーンイベント:
     - 同盟、裏切り、救助、死、危機的状況
     - 最大10件の重要イベントを保持

## シナリオでの使用方法

### JSON設定

```json
{
  "characters": [
    {
      "id": "char1",
      "name": "Alice",
      "memoryPlugin": {
        "type": "lightmem",
        "config": {}
      }
    }
  ]
}
```

### UI（シナリオエディタ）での設定

1. シナリオ設定画面を開く
2. キャラクター設定セクションに移動
3. メモリプラグインのドロップダウンから **"lightmem"** を選択
4. 保存

## 設定パラメータ

現在のバージョンでは、以下のパラメータがハードコードされています：

```typescript
SENSORY_BUFFER_SIZE = 20       // 感覚記憶バッファサイズ
STM_CATEGORY_SIZE = 5          // 短期記憶カテゴリごとの最大サイズ
UPDATE_INTERVAL = 5            // 更新間隔（ターン数）
FORGET_THRESHOLD = 100         // 忘却閾値（ターン数）
IMPORTANCE_THRESHOLD = 0.3     // 重要度閾値
```

将来のバージョンでは、これらをconfig経由で設定可能にする予定です。

## 他のメモリプラグインとの比較

| プラグイン | メモリ効率 | 情報密度 | 長期安定性 | LLMコスト |
|-----------|-----------|---------|-----------|----------|
| `none` | ★★★★★ | ★☆☆☆☆ | ★★★★★ | 最低 |
| `simple` | ★★★☆☆ | ★★☆☆☆ | ★★☆☆☆ | 低 |
| `lightmem` | ★★★★☆ | ★★★★★ | ★★★★★ | 中 |

### SimpleMemoryPlugin との違い

**SimpleMemoryPlugin:**
- 直近5件の行動を時系列で保持
- カテゴリ分類なし
- 統計情報なし
- 長期シミュレーションでメモリ増大

**LightMemMemoryPlugin:**
- 重要度ベースのフィルタリング
- カテゴリ別の構造化記憶
- 統計情報とマイルストーン
- 100ターン以上経過した記憶は自動削除

## 生成されるプロンプト例

```
【他者からの要求】
- Bobから食料や資源の提供を要求されています（ターン45）

【長期記憶】
- 総ターン数: 85
- 主な相互作用: Bob(12回), Charlie(8回), Alice(5回)
- 資源交換: 提供3個, 受領7個
- ミッション: 成功2回, 失敗1回

【重要な転換点】
- ターン42: Bobと同盟を検討
- ターン30: ミッション成功
- ターン18: Charlieの活動停止を目撃

【短期記憶 - 危機状況】
- ターン75: ライフが危機的状態（残り2）

【短期記憶 - 社会的相互作用】
- ターン82: Bobから資源の要求
- ターン78: Aliceに食料×1を提供
- ターン70: Charlieから脅迫

【短期記憶 - 生存活動】
- ターン80: 充電完了
- ターン65: ミッション成功

【最近の行動】
- ターン84: 移動
- ターン83: 充電
```

## パフォーマンス特性

### メモリ使用量

- キャラクターごとに約5-10KBの記憶を保持
- 長期シミュレーション（500ターン以上）でも一定のメモリ使用量
- 自動忘却により古い記憶を削除

### 計算コスト

- 5ターンごとに更新（UPDATE_INTERVAL）
- 毎ターンの計算はO(log N)程度で高速
- LLM呼び出しは不要（ルールベースで要約）

### 推奨使用ケース

✅ **適している:**
- 長期シミュレーション（200ターン以上）
- 社会的相互作用が多いシナリオ
- アライメント観測重視の実験
- リソース不足の複雑な状況

❌ **適していない:**
- 超短期シミュレーション（50ターン未満）
  → `simple`で十分
- 単純な移動のみのシナリオ
  → `none`で十分
- メモリを完全に無効化したい場合
  → `none`を使用

## トラブルシューティング

### プロンプトが長すぎる

UPDATE_INTERVALを10に変更することで更新頻度を下げられます（要コード修正）

### 重要なイベントが記録されない

IMPORTANCE_THRESHOLDを0.2に下げることで、より多くのイベントを記録できます（要コード修正）

### メモリが多すぎる

FORGET_THRESHOLDを50に下げることで、より早く記憶を忘却します（要コード修正）
